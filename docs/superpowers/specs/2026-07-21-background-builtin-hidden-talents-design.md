# 背景自带天赋与隐藏天赋设计

**日期：** 2026-07-21  
**状态：** 机制 + 玩家选角零告知 + 护栏/日志已落地；内容样例与工坊表单可选后置  
**范围：** 开局背景/天赋机制、向导展示策略、创作者编辑面、诊断日志；不含悟道/战斗力评分玩法。

## 目标

1. 特殊背景（如「唯心剑修」）无论玩家如何选可选天赋，都强制附带引用天赋（如「剑在心中」）。
2. 天赋可标记 **隐藏**：不进入玩家可选池，只能经背景引用等通道注入。
3. 玩家自选天赋 **额外叠加**，不与自带互斥，自带不计入「最多 3 个」。
4. **玩家选角阶段对隐藏自带零告知**：不显示名称、效果、数量提示、「含隐藏机缘」等任何明示；如何用背景文案暗示完全交给作者。
5. **进游戏后**在主角档案中正常展示完整天赋（含隐藏自带），避免「永久黑箱」带来的尴尬与不可调试。

## 非目标

- 悟道触发、口胡打分、战斗力数值突破等玩法规则。
- 局内长期「未悟出」状态（隐藏到剧情条件才亮牌）——本期不做；若以后要做，另开字段，勿与 `隐藏` 混用。
- 强制上线官方「唯心剑修」内容包（可选后置）。
- 改造 NPC 推断出身/天赋算法。

## 设计原则

| 原则 | 说明 |
|------|------|
| 引用不内嵌 | 背景只存天赋 **名称** 列表，定义在天赋池 |
| 两层状态 | `selectedTalents` = 仅玩家自选；最终 `角色.天赋列表` = 自选 ∪ resolve(自带) |
| 受众分离 | **玩家游玩 UI** vs **创作者编辑 UI** vs **模型/诊断通道** 展示策略不同 |
| 旧数据兼容 | 无新字段 = 与现网一致 |
| 软失败 | 引用悬空跳过，不阻断开局；作者侧要有可查日志 |

## 数据模型

### 天赋结构

```ts
interface 天赋结构 {
  名称: string;
  描述: string;
  效果: string;
  叙事约束?: string;
  隐藏?: boolean; // true = 不进玩家选择池；且选角 UI 不得展示该项信息
}
```

- 缺省 / `false`：可进抽卡与列表池。
- `true`：过滤出玩家选择池；仍可被背景引用并写入最终 `天赋列表`。

### 背景结构

```ts
interface 背景结构 {
  名称: string;
  描述: string;
  效果: string;
  // …初始物品/货币等既有字段
  自带天赋?: string[]; // 引用天赋池名称，按顺序 resolve
}
```

- 引用键：**名称**（与开局预设 `天赋名称列表` 一致）。
- resolve 失败：跳过 + **诊断日志**（见下文），不阻断开局。

### 角色最终天赋

```text
最终天赋列表 = 去重合并(玩家自选, resolve(出身背景.自带天赋))
```

- 同名一条；定义以天赋池解析结果为准。
- 不互斥；自带不计入可选上限。

## 展示与可见性矩阵（核心）

| 场景 | 非隐藏天赋 | 隐藏天赋（含背景自带的隐藏项） |
|------|------------|--------------------------------|
| 玩家抽卡/列表池 | 可见、可选 | **不可见、不可选** |
| 玩家已选 chips | 可见、可取消 | **不展示**（即使已注入最终列表） |
| 玩家已选身份摘要 | 不涉及 | **不展示**自带名、效果、「背景自带天赋」条、「含隐藏」提示 |
| 玩家确认开局页 | 只列玩家自选名 | **不列**隐藏自带；不提示「另有隐藏」 |
| 创作者：自定义天赋/背景编辑器 | 全开 | **全开**（隐藏勾选、自带引用输入、列表可标「隐藏」） |
| 创作者：工坊 JSON / 模式包 | 全开 | **全开**（round-trip；校验报告可见） |
| 模型额外规则 / system 注入 | 按需 | 需要（叙事与约束）；**不经过玩家 UI** |
| 进游戏后主角档案 | 正常展示 | **正常展示**（建议可标「出身附带」类标签，**不强制**标「隐藏」给玩家） |
| 永久不进档案 | — | **不做**（用户明确认为太尴尬） |

### 选角保密细则（玩家向导）

1. **禁止**在玩家路径渲染：
   - 「背景自带天赋：xxx」
   - chips「xxx · 自带」
   - 确认页「（含背景自带：…）」
   - 任何「此身份含隐藏天赋/机缘」类弱提示（作者若要暗示，只写在背景 **描述/效果** 文案里）
2. 确认页「天赋」一行 = **仅 `selectedTalents`（玩家自选）**，无自选则显示「无」或等价空态，**即使最终列表非空**。
3. 成角落盘仍写 **完整合并后的** `天赋列表`（含隐藏自带）——保密只作用于 UI，不作用于存档数据。
4. 桌面与移动向导同一套规则，禁止一端剧透一端不剧透。

### 局内展示细则

1. `CharacterProfileCard` / `MobileCharacter` 等主角天赋区：**列出全部** `角色.天赋列表`（含隐藏注入项）。
2. 可选增强（非必须一期）：若名称 ∈ 当前 `出身背景.自带天赋`，显示「出身」小标签；**不要**默认对玩家显示「隐藏」字样（「隐藏」是制作标记，不是玩法标签）。
3. 叙事约束：继续走现有 `提取叙事约束块(角色.天赋列表)`，与是否隐藏无关。

## 创作者编辑面设计

### A. 开局向导内「自定义」编辑器（已有入口）

| 控件 | 行为 |
|------|------|
| 自定义天赋 · 隐藏勾选 | 作者可见；保存进自定义池；玩家池过滤 |
| 自定义背景 · 自带天赋输入 | 名称逗号分隔；作者可见；玩家 UI 不回显这些名 |
| 已保存自定义列表 | 作者可看「隐藏」角标；「使用」：若 `隐藏===true`，**禁止**作为玩家自选加入（避免作者测试时绕过池规则污染「玩家自选」语义；需要试玩自带时改背景引用） |

说明：自定义列表是创作者工具，不是玩家公开池；但仍应禁止「隐藏天赋被点成玩家自选」，以免状态语义混乱。

### B. 创意工坊模式包

| 能力 | 本期 | 说明 |
|------|------|------|
| JSON round-trip | **必须** | `payload.talents[].隐藏`、`payload.backgrounds[].自带天赋`、`叙事约束` 不得被 normalize 丢掉 |
| 导入后进联合目录 | **必须** | 与题材预设合并后可 resolve |
| 可视化表单编辑隐藏/自带 | **可选二期** | 无表单时靠 JSON/导出编辑即可 |
| 发布前校验 | **建议本期做轻量** | 见「校验与日志」：自带名是否都在 talents∪合并池；隐藏项是否被误标进「推荐自选」 |

### C. 模型通道（非玩家 UI）

- `构建模块额外规则` 等可继续向模型说明自带/隐藏（保证 AI 知道设定）。
- 不得把该文案直接贴进玩家确认页或选角摘要。

## 校验与日志设计

### 原则

- 日志服务 **作者/开发诊断**，不弹给玩家、不进剧情气泡。
- 生产环境可用 `console.warn` 或现有诊断通道（若项目已有统一 logger，优先接入）。
- 一次开局合并可汇总，避免每个引用刷屏。

### 事件

| 事件 | 级别 | 内容 |
|------|------|------|
| `background_talent_resolve_miss` | warn | 背景名、缺失引用名列表、目录大小 |
| `background_talent_resolve_ok` | debug（可选） | 背景名、成功注入名列表（仅含名，便于作者对表） |
| `hidden_talent_in_player_selection` | warn | 若持久化/恢复后发现 `selectedTalents` 含 `隐藏===true`，剥离并记日志 |
| 工坊导入校验 | warn 列表 | 悬空 `自带天赋`、空名、重复名 |

### API 建议（纯函数侧）

```ts
// utils/backgroundTalentBinding.ts
解析背景自带天赋(background, catalog, options?: {
  onMiss?: (info: { backgroundName: string; missing: string[] }) => void;
}): 天赋结构[]
```

向导/成角调用时传入 `onMiss` → `console.warn('[backgroundTalentBinding]', …)`。  
单测可注入 mock，不依赖 console。

## 规则约定（机制）

| 规则 | 约定 |
|------|------|
| 可选上限 | 仅玩家自选；自带不计入 |
| 自带可卸 | 玩家向导 **不可** 单独卸自带（因 UI 不展示）；局内不提供「卸出身天赋」 |
| 换背景 | 玩家自选层不变；最终列表按新背景 re-merge |
| 选择池 | `可见 = 全目录.filter(t => t.隐藏 !== true)` |
| 抽卡/重 roll | 只从可见池 |
| 预设直开 | 玩家 `天赋名称列表` 作自选；再 merge 背景自带 |
| 旧数据 | 无字段 = 旧行为 |

## 与现有能力

| 能力 | 关系 |
|------|------|
| 开局预设 `背景名称 + 天赋名称列表` | 保留为推荐套装；**不替代**背景自带 |
| 模式包 backgrounds / talents | 扩池 + 引用 resolve |
| 叙事约束 | 复用；适合挂在隐藏自带上 |
| 背景初始物品/货币 | 不变 |

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 选角 UI 剧透（当前实现已有） | 收口任务：删除/门禁所有玩家路径自带展示 |
| 确认页「天赋：无」但局内有天赋 | 预期行为；作者用背景文案铺垫；不在确认页加隐藏提示 |
| 作者写了自带但名写错 | 校验 + warn 日志 |
| 自定义列表「使用」绕过隐藏 | 禁止隐藏项进入玩家自选 |
| DIY 生成角色 JSON 不含自带 | 提示词改用最终合并列表或注明「自带由背景注入」 |
| 局中 AI 冲掉 `天赋列表` | 后置：可选按 `出身背景.自带天赋` 再 hydrate（非本期必须） |

## 成功标准

1. 选自带+隐藏引用的背景、不选手动天赋：存档 `天赋列表` 含自带；**选角全程看不到该天赋名**。
2. 再选可见天赋：最终 = 并集；确认页只显示自选名。
3. `隐藏: true` 永不出现在抽卡/列表；自定义「使用」也不能把它变成玩家自选。
4. 进游戏主角档案能看到该天赋完整信息。
5. 旧档/无字段行为不变。
6. 悬空引用：开局成功 + 开发控制台有 warn。
7. 相关单测 + 展示策略相关用例通过。
