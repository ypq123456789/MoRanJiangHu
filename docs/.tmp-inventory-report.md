## 五、为什么会有这么多

关键线索：**`.tmp-web-*` 系列有 30+ 个目录，每个约 136 MB**。
它们对应历次发布时的独立构建输出目录。

这与已知的沙箱约束有关：**同一 `outDir` 二次 build 会 EPERM**，
所以每次发布都要换一个全新的临时目录 —— 目录越攒越多，且没有任何清理环节。

---

## 六、建议

### 建议清理（安全，可回收约 8.7 GB）

**除** `.tmp-check-html.py` / `.tmp-check-version.py` 之外的全部 `.tmp-*` 条目。

这些是历史构建/诊断残留，已无任何引用。

### 建议保留

- `.tmp-check-html.py`、`.tmp-check-version.py`：因被 git 跟踪，删除需额外提交，且体积可忽略。

### 长效机制建议（可选，需要单独授权）

1. 在发布脚本收尾处，顺手清理自己产生的临时目录（用完即删）。
2. 或加一个 `npm run clean:tmp` 脚本，只清理**超过 N 天**的 `.tmp-*`，保留最近一次。
3. 在 `.gitignore` 中已忽略的前提下，把这两个被跟踪的 `.py` 用 `git rm --cached` 摘出跟踪。
